## 📦 Что нового в версии 1.1.0

### ✨ Основная функциональность

#### Обработка ошибок телеметрии (TELEMETRY_DATA_FALSE)

Добавлена автоматическая обработка ошибок при передаче телеметрии на сервер.

**Преимущества:**
- ✅ Автоматическая повторная отправка при получении команды `DATA_FALSE (00 02)` от сервера
- ✅ Немедленная реакция на ошибку (не требуется ждать следующего цикла отправки)
- ✅ Сохранение последних данных телеметрии для повторной передачи
- ✅ Счётчик ошибок для мониторинга качества связи
- ✅ Минимальная задержка между ошибкой и повтором

## 🔧 Технические детали

### Добавленные компоненты

#### 1. Хранение данных телеметрии (`Data.cpp`)

```cpp
static MSGQUEUE_OBJ_t LastSentTelemetry = {};  // Последние отправленные данные
static uint32_t TelemetryErrorCount = 0;       // Счётчик ошибок отправки
```

**Описание**: Автоматическое сохранение данных телеметрии перед каждой отправкой.

#### 2. Функция повторной отправки (`Data.cpp`)

```cpp
void ResendLastTelemetry(void);
```

**Описание**: Немедленная повторная отправка последних данных телеметрии при ошибке.

**Действия функции:**
- Проверка валидности сохранённых данных
- Отправка данных с уже рассчитанным CRC
- Инкремент счётчика ошибок

#### 3. Обработчик команды DATA_FALSE (`CommandReceiver.cpp`)

```cpp
case TELEMETRY_DATA_FALSE:
    ResendLastTelemetry();  // Автоматический повтор
    break;
```

**Описание**: Обработка команды `00 02` от сервера с автоматическим вызовом повторной отправки.

## 🔄 Последовательность работы

```
1. Контроллер отправляет телеметрию
   └─> Автоматическое сохранение в LastSentTelemetry
   
2. Сервер получает данные
   └─> Проверка CRC / валидности
   
3а. Данные корректны ✅
   └─> Сервер отправляет DATA_OK (00 01)
   └─> Контроллер продолжает работу
   
3б. Ошибка в данных ❌
   └─> Сервер отправляет DATA_FALSE (00 02)
   └─> Контроллер получает команду
   └─> CommandReceiver вызывает ResendLastTelemetry()
   └─> Немедленная повторная отправка
   └─> TelemetryErrorCount++
```

## 🔬 Тестирование

### Рекомендуемые тесты

1. **Тест успешной передачи**
   - Отправить телеметрию
   - Убедиться что сервер отправляет `DATA_OK (00 01)`
   - Проверить что контроллер продолжает работу

2. **Тест обработки ошибки**
   - Отправить телеметрию
   - Сервер отправляет `DATA_FALSE (00 02)`
   - Убедиться что контроллер немедленно повторяет отправку
   - Проверить увеличение `TelemetryErrorCount`

3. **Тест множественных ошибок**
   - Вызвать несколько ошибок подряд
   - Проверить корректность работы счётчика
   - Убедиться что повторы не блокируют систему

### Проверка версии

Версию можно получить через команду `REQ_CMD_GET_VERSION (03 02)`:

```
Запрос:  [03 02 00] + CRC
Ответ:   [03 02 00 05 31 2E 31 2E 30] + CRC
         (строка "1.1.0")
```

Или через команду `REQ_CMD_GET_BUILD_INFO (03 04)`:

```
Ответ: "Defrost Controller v1.1.0 (Nov 12 2025 14:30:00)"
```

## 🎯 Совместимость

### Обратная совместимость

✅ **Полная обратная совместимость** с версией 1.0.0

- Все существующие команды работают без изменений

- Не требуется изменений на стороне сервера (но рекомендуется)

### Рекомендации для сервера

Рекомендуется обновить серверную часть для поддержки:
- Отправки команды `DATA_FALSE (00 02)` при обнаружении ошибки в телеметрии
- Приёма повторно отправленных данных

**Важно**: Если сервер не отправляет `DATA_FALSE`, система продолжит работать как раньше (без автоматического повтора).
