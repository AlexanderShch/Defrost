# Работа алгоритма дефростера при отключении датчиков температуры воздуха

Документ описывает поведение автоматики в `DefrostControl.cpp` при недоступности одного или нескольких каналов **температуры воздуха дефростера**: левая подача, правая подача, возврат. Кодировка: UTF-8.

**Связанные файлы:** `STM32CubeIDE/ProjectCode/DefrostControl.cpp` (структура `DefrostAirControlInputs`, функции `DefrostAirThChannelUsable`, `ComputeDefrostAirControlInputs`), `Data.cpp` / `Model` — авария по обрезкам `Sensor_AlarmFlags`.

---

## 1. Какие датчики считаются «воздушным контуром»

Индексы в `Sensor_array` (как в алгоритме):

| Индекс | Назначение |
|--------|------------|
| **0** | Температура (и RH) **левой** подачи |
| **1** | Температура (и RH) **правой** подачи |
| **2** | Температура (и RH) **возврата** |

Датчики продукта (**3**, **4**) и остальные каналы **не входят** в описанную ниже логику воздушного контура (для рыбы действуют отдельные правила `Active`, `UseInDefrost`, `Sensor_AlarmFlags`).

---

## 2. Когда канал «исправен» для автоматики

Канал **0, 1 или 2** участвует в расчётах контура подачи/возврата только если выполняется **оба** условия:

1. **`Sensor_array[i].Active == 1`** — датчик считается активным на шине (нет отключения/потери связи в логике опроса).
2. **Бит `i` в `Model::Sensor_AlarmFlags` сброшен** — нет защёлкнутой аварии «избыточная доля обрезок сырой T» в буфере (см. `Data.cpp`, `T_ClampHit` / порог `> TQ/2`).

В коде это объединено в **`DefrostAirThChannelUsable(idx)`**.

Если канал **не исправен**, его **измерения T и RH не используются** в формулах средних и баланса (см. ниже). Сырые значения по-прежнему могут отображаться на экране и уходить в телеметрию — это не отключается данной логикой.

---

## 3. Вычисляемые величины (`ComputeDefrostAirControlInputs`)

Одна функция собирает все скаляры для шага управления (режим **с продуктом** и режим **только воздух** — `ControlStep1s_AirOnly`).

### 3.1. Отфильтрованная температура

Для расчётов используется **усреднённая по буферу обрезанных значений** температура (Param 4 в подсистеме `Sensor`, не сырая T с экрана):

- `mL`, `mR`, `mRet` — в °C.

### 3.2. Средняя температура подачи `T_sup_avg_C`

- Обе подачи исправны: **`T_sup_avg_C = (mL + mR) / 2`**.
- Только левая: **`T_sup_avg_C = mL`**.
- Только правая: **`T_sup_avg_C = mR`**.
- **Обе подачи недоступны, возврат исправен:** **`T_sup_avg_C = mRet + 2 °C`** (оценка температуры подачи по возврату; константа `kSupplyTInferOffsetFromReturn_C` в `DefrostControl.cpp`).
- **Обе подачи недоступны и возврат неисправен:** **`T_sup_avg_C = 0`**.

Эта величина идёт в общий контур температуры подачи (`eT_common = supplySet_C - T_sup_avg_C`).

### 3.3. Температура для уставки влажности по возврату `T_ret_C`

- Возврат исправен: **`T_ret_C = mRet`**.
- Возврат **не** исправен: **`T_ret_C = T_sup_avg_C`** (если подач нет — получится 0; уставка `w_ret_target` строится от этой T).

Так контур влажности не опирается на «мёртвый» канал возврата, когда есть хотя бы одна подача.

### 3.4. Средняя относительная влажность подачи `RH_sup_avg`

Используются текущие RH (`Model::getCurrentVal_H`):

- Обе подачи исправны: **среднее RH левой и правой**.
- Только одна сторона: **RH этой стороны**.
- **Обе подачи недоступны, возврат исправен:** **RH с канала возврата** (индекс 2).
- **Все три канала 0..2 неисправны:** **RH = 50 %** (номинал для `w_sup_avg`).

### 3.5. Флаги исправности

`okL`, `okR`, `okRet` — признаки того, что соответствующий канал прошёл проверку из п. 2.

---

## 4. Ограничение по максимальной температуре подачи (`supplyMax_C`)

Проверка **«перегрев струй»**:

- если **левая** исправна и **`mL > supplyMax_C`** → нагрев отключается (`heatScale01 = 0`);
- если **правая** исправна и **`mR > supplyMax_C`** → то же;
- если **обе подачи неисправны**, но **возврат исправен**: сравнивается **оценка подачи** **`mRet + 2 °C`** с **`supplyMax_C`** — при превышении нагрев отключается.

Неисправный канал подачи **не участвует** в прямой проверке `mL`/`mR` (исключены ложные срабатывания).

---

## 5. Баланс лево / право (`eT_diff`, trim ТЭНов)

Разница **`eT_diff = mL - mR`** используется **только если исправны обе подачи** (`okL` и `okR`).

Если доступна **только одна** подача, **`eT_diff = 0`**: общий запрос мощности распределяется **симметрично** (без перекоса по несуществующей второй стороне).

---

## 6. Отказ датчиков Т подачи и полный отказ контура 0..2

### 6.1. Обе подачи неисправны, возврат исправен

- **`T_sup_avg_C = mRet + 2 °C`** — алгоритм **продолжает** работу по воздушному контуру (ПИ по подаче, лимиты, влажность с RH возврата).
- **`eT_diff = 0`** (баланс лево/право не используется).

### 6.2. Полный отказ всех трёх каналов (левая подача, правая подача, возврат)

Если **`okL == 0` и `okR == 0` и `okRet == 0`**:

- **`T_sup_avg_C = 0`**.
- **`heatScale01` принудительно обнуляется** — **нагрев по воздушному контуру отключается**.

Так исключается ПИ «вслепую», когда нет ни подачи, ни возврата.

Режим **«только воздух»** (`ControlStep1s_AirOnly`) использует **те же правила** для `T_sup_avg_C`, RH, лимита `supplyMax`, `eT_diff` и отключения нагрева при полном отказе 0..2.

---

## 7. Датчики продукта (рыба), индексы 3 и 4

Отдельно от воздушного контура:

- канал учитывается в фазах/ограничениях по продукту, если **`Active == 1`**, **`UseInDefrost != 0`** и **нет бита** в **`Sensor_AlarmFlags`** для этого индекса;
- при «выпадении» одного из двух датчиков рыбы алгоритм переходит к сценарию с одним датчиком или в режим **только по воздуху** (см. основной документ `DefrostControl_Algorithm_RU.md`).

## 8. Краткая таблица сценариев (подача / возврат)

| Левая подача | Правая подача | Возврат | Поведение (суть) |
|--------------|---------------|---------|-------------------|
| ✓ | ✓ | ✓ | Классика: среднее T подачи, среднее RH, `eT_diff` по двум сторонам, `T_ret` с возврата |
| ✓ | ✗ | ✓ | `T_sup_avg = mL`, RH левый, баланс выкл., лимиты только по `mL`, `T_ret` с возврата |
| ✗ | ✓ | ✓ | Симметрично предыдущему для правой стороны |
| ✓ | ✓ | ✗ | Как две подачи; `T_ret` для влажности = средняя подача |
| ✓ | ✗ | ✗ | Одна подача; `T_ret` = `mL` |
| ✗ | ✓ | ✗ | Одна подача; `T_ret` = `mR` |
| ✗ | ✗ | ✓ | **Оценка подачи:** `T_sup_avg = T_ret + 2 °C`, RH из возврата, баланс выкл.; лимит `supplyMax` по **`T_ret+2`** |
| ✗ | ✗ | ✗ | **Полный отказ 0..2:** `T_sup_avg=0`, **нагрев по воздуху выкл.**; RH=50 % |

(✓ = канал исправен по п. 2, ✗ = нет.)
