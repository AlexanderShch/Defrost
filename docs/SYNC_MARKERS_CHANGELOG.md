## 📋 Что изменено

### 1. Добавлены константы sync-маркеров

### 2. Создана функция отправки с sync-маркерами

**Файл**: `STM32CubeIDE/ProjectCode/ModBus.cpp`

**Новая функция**: `WriteToServerWithSync(uint8_t* Data, int length)`

**Формат пакета**:
```
[AA 55] [Данные] [55 AA]
└─┬──┘  └───┬──┘ └──┬──┘
START    Data     END
```

**Как работает**:
1. Добавляет `0xAA 0x55` в начало пакета
2. Копирует данные (с уже рассчитанным CRC)
3. Добавляет `0x55 0xAA` в конец пакета
4. Отправляет через UART4 с использованием мьютекса

**Особенности**:
- Автоматически проверяет размер буфера
- Если пакет слишком большой, отправляет без sync (обратная совместимость)
- Использует мьютекс UART4 для защиты от конфликтов

### 3. Изменена отправка телеметрии

**Файл**: `STM32CubeIDE/ProjectCode/Data.cpp`

**Функция**: `TX_ToServer()`

**БЫЛО**:
```cpp

```

**СТАЛО**:

- **+4 байта на пакет (+8%)**

## ✅ Преимущества

### 1. Надёжность
- **Быстрое восстановление** после ошибок CRC
- **Чёткая граница** пакетов: легко найти начало следующего
- **Двойная проверка**: sync-маркеры + CRC

### 2. Отладка
- **Визуально понятно** в hex-дампе: `AA 55 ... 55 AA`
- **Легко найти** границы пакетов при анализе логов
- **Быстрое обнаружение** рассинхронизации

### 3. Совместимость
- **Автоопределение** на сервере: с sync или без
- **Обратная совместимость**: старый контроллер будет работать
- **Плавный переход**: можно обновлять контроллеры постепенно

## 📝 Заметки разработчика

### Важные моменты:

1. **CRC рассчитывается ДО добавления sync-маркеров**
   - Sync-маркеры НЕ входят в расчёт CRC
   - CRC покрывает только: Type + Data

2. **Размер буфера**
   - `TxBufferWithSync[MAX_MB_BUFSIZE + 4]` - учитываем +4 байта
   - При превышении - fallback на `WriteToServer()` без sync

3. **Мьютекс UART4**
   - `WriteToServerWithSync()` использует тот же мьютекс
   - Защита от конфликта с программированием датчиков

4. **Семафоры TX/RX**
   - Логика RS-485 Half Duplex сохранена
   - Проверка занятости TX/RX перед передачей

5. **Команды от сервера**
   - Приём БЕЗ sync-маркеров (старый формат)
   - Только отправка контроллером использует sync

### Потенциальные проблемы:

❌ **Проблема**: Если в данных встречается последовательность `AA 55` или `55 AA`
✅ **Решение**: Это не проблема, так как:
   - Сервер ищет `AA 55` именно в начале
   - Затем проверяет `55 AA` на ожидаемой позиции (Type + Length + 2)
   - Даже если в data есть `AA 55`, это не обманет парсер

❌ **Проблема**: Буфер переполнен (>MAX_MB_BUFSIZE)
✅ **Решение**: Fallback на `WriteToServer()` без sync

❌ **Проблема**: Старый сервер не понимает sync-маркеры
✅ **Решение**: Обновить сервер ИЛИ откатить контроллер на v1.1.0

## 🔍 Проверка в hex-дампе

### Пример пакета телеметрии:

```
AA 55                    ← SYNC_START
00                       ← Type (телеметрия)
01 02 03 ... (42 байта) ← Данные (температуры, влажности и т.д.)
A3 4F                    ← CRC16
55 AA                    ← SYNC_END
```

### Пример ответа на команду GET_VERSION:

```
AA 55                    ← SYNC_START
03                       ← Type (REQUEST)
02                       ← Code (GET_VERSION)
00                       ← Status (OK)
05                       ← DataLen (5 символов "1.2.0")
31 2E 32 2E 30           ← Data ("1.2.0")
XX XX                    ← CRC16
55 AA                    ← SYNC_END
```
