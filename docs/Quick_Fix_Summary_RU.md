### 1. **Проблема с телеметрией**
**Симптом:** При быстром ответе сервера (<100 мс) контроллер отправлял ошибочный пакет `00 00 01 00 01 B4`

**Причина:**
- Конфликт между `Master_Request` (ждал ответ 100 мс) и `CommandReceiver` (постоянно слушал)
- Двойной перезапуск приёма → ложное IDLE на пустой линии
- Обработка нулевого буфера как команды 0x00/0x00

**Решение:**
1. Создана функция `Master_SendTelemetry()` - отправка БЕЗ ожидания ответа
2. Ответ обрабатывается асинхронно через `CommandReceiver`
3. Добавлена защита от фантомной команды 0x00/0x00

**Файлы:**
- `ModBus.cpp`: добавлена функция `Master_SendTelemetry()` (строки 1074-1154)
- `ModBus.cpp`: изменена `WriteToServer()` (строки 1156-1200)
- `CommandReceiver.cpp`: добавлена проверка команды 0x00/0x00 (строки 731-737)

### 2. **Конфликт UART4**
**Симптом:** UART4 используется тремя процессами одновременно:
- Телеметрия (отправка на сервер)
- Приём команд (от сервера)
- Программирование датчиков

**Причина:**
- Нет синхронизации доступа к UART4
- Возможны коллизии на RS-485 Half Duplex

**Решение:**
Добавлен мьютекс `UART4_Mutex` для защиты доступа

**Файлы:**
- `main.c`: объявление и создание мьютекса (строки 159-163, 317-318)
- `ModBus.cpp`: использование в `WriteToServer()` (строки 1165-1195)
- `ModBus.cpp`: использование в `ProgrammingSensor()` (строки 465-495)

## ⚠️ Важно для разработчиков

### Если добавляете новый код, использующий UART4:

**ВСЕГДА захватывайте мьютекс:**

```cpp
// Захват мьютекса
osStatus_t mutexStatus = osMutexAcquire(UART4_MutexHandle, osWaitForever);
if (mutexStatus != osOK)
{
    return;  // Ошибка
}

// Работа с UART4
// ...

// Освобождение мьютекса
osMutexRelease(UART4_MutexHandle);
```

### Не забудьте добавить extern в начале файла:

```cpp
extern osMutexId_t UART4_MutexHandle;
```
