# Алгоритм управления дефростером (DefrostControl)

Документ описывает алгоритм управления, реализованный в `STM32CubeIDE/ProjectCode/DefrostControl.cpp`.

## 1. Физическая модель установки (кратко)

- **Два потока подачи**: слева и справа, каждый формируется парой вентиляторов, продувающих пару ТЭНов.
- **Возврат (return)**: воздух забирается через всасывающий люк по центру потолка; точка измерения расположена в «чердачном» пространстве над люком.
- **Управление влажностью**: форсунка (впрыск воды) и вытяжной вентилятор.
- **Объект управления**: рыба в загрузке (тепловая инерция + фазовый переход около 0°C).

## 2. Измерения и индексация датчиков

Алгоритм использует текущие значения из `Model::getCurrentVal_T/H(...)` (масштаб 0.1 единицы).

### 2.1. Принятая привязка каналов (по умолчанию)

Индексы соответствуют текущей конфигурации `SQ=7`:

- **0**: подача слева, `T_sup_L` и `RH_sup_L`
- **1**: подача справа, `T_sup_R` и `RH_sup_R`
- **2**: возврат/смешение (чердак над всасыванием), `T_ret` и `RH_ret`
- **3**: температура продукта (датчик 1), `T_fish_1`
- **4**: температура продукта (датчик 2), `T_fish_2`

Если в прошивке поменяется порядок датчиков, требуется обновить индексы в начале `DefrostControl.cpp`.

## 3. Исполнительные механизмы (выходы)

Алгоритм выставляет биты регистра `Model::DFR`:

- Вентиляторы: `Vent1_Left`, `Vent2_Left`, `Vent1_Right`, `Vent2_Right`
- ТЭНы: `Ten1_Left`, `Ten2_Left`, `Ten1_Right`, `Ten2_Right`
- Влажность: `_Inj` (форсунка), `_Out` (вытяжка)

## 4. Структура управления

Алгоритм разделён на три слоя:

1) **Ограничитель качества/безопасности** (safety limiter)  
2) **Регулирование температуры подачи** (общий уровень + баланс лево/право)  
3) **Регулирование влажности** (форсунка + вытяжка)  

Логика выполняется в функции `DefrostControl_Update1s()` с периодом 1 секунда.

## 5. Фазы процесса

Фаза выбирается по более холодному датчику продукта:

- **WarmUp**: `T_fish_cold < -2°C`
- **Plateau**: `-2°C ≤ T_fish_cold < 1°C`
- **Finish**: `T_fish_cold ≥ 1°C`

Почему: около 0°C динамика резко меняется из‑за скрытой теплоты плавления, поэтому уставки и ограничения должны быть другими.

## 6. Ограничения качества (safety limiter)

Алгоритм вычисляет:

- `T_fish_hot = max(T_fish_1, T_fish_2)`  
- `T_fish_cold = min(T_fish_1, T_fish_2)`  
- `ΔT_fish = T_fish_hot - T_fish_cold`  

Далее формируется коэффициент `heatScale01` (0..1), который уменьшает запрос мощности нагрева.

Ограничения (по умолчанию зависят от фазы):

- **Потолок температуры “горячей” точки продукта**: если `T_fish_hot ≥ fishHotMax_C`, нагрев запрещается (`heatScale01=0`).
- **Ограничение по скорости прогрева**: если `(T_fish_hot - T_fish_hot_prev)/dt` превышает `fishHotRateMax_Cps`, нагрев дополнительно уменьшается.
- **Ограничение по неравномерности**: если `ΔT_fish > fishDeltaMax_C`, нагрев запрещается.
- **Ограничение по температуре струй**: если `T_sup_L` или `T_sup_R` выше `supplyMax_C`, нагрев запрещается.

Назначение: не допустить перегрева поверхности и больших градиентов температур, которые обычно являются первопричиной ухудшения качества.

## 7. Регулирование температуры (2 стороны)

### 7.1. Общая составляющая (common-mode)

Используется средняя температура подачи:

`T_sup_avg = (T_sup_L + T_sup_R)/2`

Ошибка:

`eT_common = T_sup_set - T_sup_avg`

Регулятор: **PI** с anti-windup, выход — в “эквивалентах ТЭНа” на сторону:

- диапазон: `0..2` (два ТЭНа на сторону)
- итоговый запрос масштабируется `heatScale01`

### 7.2. Баланс лево/право (differential trim)

Ошибка:

`eT_diff = T_sup_L - T_sup_R` (цель — 0)

Коррекция:

`trim = kTrim * eT_diff`, затем ограничение по модулю.

Запрос на стороны:

- `uLeft = clamp(uCommon - trim, 0..2)`
- `uRight = clamp(uCommon + trim, 0..2)`

Назначение: исключить перекос потоков при неодинаковых условиях слева/справа.

### 7.3. Дискретизация ТЭНов (скважность)

Поскольку ТЭНы бинарные, запрос `uSide` переводится в две скважности:

- `Ten1Duty = clamp(uSide, 0..1)`
- `Ten2Duty = clamp(uSide - 1, 0..1)`

Далее применяется **sigma-delta** (1 Гц), чтобы “размазать” включения и получить среднюю мощность, близкую к заданной скважности.

Дополнительно применяется **минимальная выдержка** (hold) на переключение для защиты силовых реле/контакторов.

### 7.4. Вентиляторы

В текущей реализации вентиляторы держатся включёнными постоянно, пока алгоритм активен.

Почему: стабильный расход воздуха делает систему более идентифицируемой и уменьшает риск локального перегрева ТЭНов.

## 8. Управление влажностью (форсунка + вытяжка)

### 8.1. Почему не RH

RH зависит от температуры. Два режима с одинаковым RH могут иметь разную “сушащую способность”.
Поэтому алгоритм переводит `(T_ret, RH_ret)` в **абсолютную влажность** (humidity ratio) `w`.

### 8.2. Расчёт абсолютной влажности

Используется приближение Магнуса–Тетенса для давления насыщенного пара `e_s(T)` и далее:

- `p_v = RH * e_s(T)`
- `w = 0.62198 * p_v / (P - p_v)`

`P` принимается постоянным (101.325 кПа).

### 8.3. Стратегия управления

- Уставка задаётся как `RH_target` при текущей `T_ret`, затем переводится в `w_target`.
- Ошибка: `wErr = w_target - w_ret`.

**Форсунка (_Inj)**:

- работает по скважности (sigma-delta 1 Гц) при `wErr` выше мёртвой зоны
- имеет минимальную выдержку переключений (hold), чтобы не “щёлкать” клапаном/насосом

**Вытяжка (_Out)**:

- бинарная с гистерезисом и минимальным временем включения/выключения

**Взаимоисключение**:

- если вытяжка включена, форсунка подавляется (чтобы не тратить энергию и не создавать неидентифицируемую “борьбу” актуаторов).

## 9. Включение/отключение алгоритма

Публичные функции:

- `DefrostControl_Init()` — сброс внутренних состояний
- `DefrostControl_SetEnabled(uint8_t)` — внешний флаг “можно управлять”
- `DefrostControl_Update1s()` — шаг управления 1 сек

Алгоритм не действует, если:

- `enabled == 0`
- включён ручной режим: `Model::Flag_DFR_manual != 0`

## 10. Рекомендации по размещению 2 датчиков продукта

Чтобы одновременно ускорять процесс и не портить качество:

- один датчик ставить в **самую холодную/инерционную** точку (центр массива, глубже) — для оценки “готовности”
- второй датчик ставить в **самую рисковую по перегреву** точку (ближе к поверхности/краю в зоне струи) — для ограничений качества

## 11. Что настраивать на объекте (обязательно)

Параметры, требующие подбора:

- уставки `T_sup_set` по фазам и пороги фаз
- ограничения `fishHotMax`, `fishHotRateMax`, `fishDeltaMax`, `supplyMax`
- PI коэффициенты температуры (`kp`, `ki`) и коэффициент балансировки `kTrim`
- параметры влажности: мёртвая зона `wDeadband`, коэффициент форсунки `k`, гистерезис/времена выдержки вытяжки
- минимальные выдержки переключений (hold) для ТЭНов и форсунки — под тип силовой части

Критерий правильной настройки: отсутствие длительных перерегулирований `T_sup`, отсутствие роста `T_fish_hot` с высокой скоростью, и отсутствие большого `ΔT_fish` на протяжении процесса.
