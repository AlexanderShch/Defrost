# Чек-лист ветвлений алгоритма при отказе датчиков Т

## Актуальный порядок работы

Контроллер опрашивает датчики и модуль ввода-вывода по Modbus RTU через UART5. Для каждого запроса ожидаемую длину вычисляют по функции и числу запрошенных регистров или битов. Обычно это 9 байт для двух регистров, 7 для одного регистра или 16 дискретных входов или выходов, 8 для подтверждения записи и 5 для ответа с исключением Modbus.

До обновления показаний контроллер проверяет состояние UART и факт приёма, границы кадра, адрес, функцию и соответствие фактической длины запросу. Для чтения проверяется ByteCount, затем CRC по фактически принятому кадру. Ответ с исключением проверяется отдельно по длине и CRC. При ошибке чтения контроллер удерживает предыдущие показания.

После трёх подряд ошибок приёма активный датчик переходит в Active=0. Контроллер продолжает пробные опросы. Неудачные опросы неактивного устройства не увеличивают счётчики ошибок, не попадают в минутную сводку и не создают события. Первый правильный ответ снова включает устройство. Если до отключения была открыта серия сбоев, правильный ответ завершает её событием восстановления. UseInDefrost управляет участием в регулировании независимо от активности на шине.

Минутная диагностика GET_SENSOR_DIAG (03/0A) возвращает 85 байт данных со статистикой по устройствам и снимком последнего сбоя. Счётчики периода сбрасываются при формировании ответа. Сбой активного устройства и его восстановление отдельно передаются через очередь событий с подтверждением.


Источник: программа испытаний + `DefrostControl.cpp`.
Кодировка: UTF-8.

Цель: подтвердить, что при **наличии** и **отсутствии** датчиков температуры алгоритм проходит нужную контрольную точку ветвления. Доказательство — поля регулярного лога, а не «на глаз» по ТЭНам.

Канал **годный** (участвует в расчёте), если одновременно: `Active=1`, `UseInDefrost=1`, бит `Sensor_AlarmFlags` сброшен.

Индексы: **0** левая подача, **1** правая подача, **2** возврат, **3** продукт левый, **4** продукт правый.

Обратный расчёт: `T_sup_avg = supplySet_C[phase] − eT_common`.
Маркер режима без продукта (AirOnly): в логе `fishHot_C = 0` и `fishCold_C = 0`.
Маркер «стороны нагрева сбалансированы»: `trim_TEN = 0`.
Маркер полного отказа воздуха 0…2: `heatScale01 = 0`.

`T_filt_C[0…5]` пишется всегда; в расчёт идут только годные каналы.

## Параметры регулярного лога (`ControlLogPayload_t`)

Кадр Type=0x00 / Code=0x01, 89 байт. Снимок заполняется в `ControlStep1s` / `ControlStep1s_AirOnly`. На сервере колонки `T_filt_0…T_filt_5` и поля ниже.

| Поле лога | Ед. | Функция в алгоритме | Как подтверждает ветку |
|-----------|-----|---------------------|------------------------|
| T_filt_C[0] | °C | Отфильтрованная T левой подачи (Param 4). При годном канале это **mL**: среднее T_sup, разность eT_diff, лимит supplyMax. | A1–A2, A4–A5: сравнить с ожидаемым mL. При исключении канала 0 в расчёт не идёт, значение в логе может остаться. |
| T_filt_C[1] | °C | Отфильтрованная T правой подачи. При годном канале это **mR**: те же контуры, что у канала 0, с другой стороны. | A1, A3, A4, A6. Мёртвый канал не участвует в T_sup и не гасит нагрев по supplyMax. |
| T_filt_C[2] | °C | Отфильтрованная T возврата. При годном канале это **mRet**: T_ret для уставки влажности; при отказе обеих подач T_sup = mRet + 2 °C. | A1–A3, A7: T_ret = mRet. A4–A6: T_ret берётся не из этого поля, а из T_sup. A7: eT_common = supplySet − (это поле + 2). |
| T_filt_C[3] | °C | Отфильтрованная T левого датчика продукта. При годном канале входит в fishHot / fishCold / фазу / автостоп / лимитеры качества. | P1: max/min с каналом 4. P2: fishHot = fishCold = это поле. P4: в расчёте нет, в логе может быть ненулевым. |
| T_filt_C[4] | °C | Отфильтрованная T правого датчика продукта. Та же роль, что у канала 3, для второй точки загрузки. | P1 / P3. Не путать с fishHot_C / fishCold_C — те уже результат ветвления. |
| T_filt_C[5] | °C | Канал 5 (рабочая T дефростера). В лог пишется, в контуры подачи / возврата / продукта **не входит**. | Не использовать как доказательство веток A/P. |
| phase | 0 / 1 / 2 | Текущая фаза: 0 WarmUp, 1 Plateau, 2 Finish. По ней берутся supplySet, supplyMax, RH_target и лимиты продукта. | С продуктом: SelectPhase(fishCold). Без продукта: SelectPhaseByTime(runtime). P5, P4, C2. |
| eT_common | °C | Ошибка контура подачи: supplySet_C[phase] − T_sup_avg. Вход ПИ-регулятора температуры. | Обратный расчёт **T_sup_avg = supplySet[phase] − eT_common**. Главное доказательство веток A1–A8. |
| heatScale01 | 0…1 | Ограничитель мощности нагрева. С продуктом: потолок T_hot, скорость прогрева, ΔT_fish, supplyMax, отказ 0…2. В AirOnly: только supplyMax и отказ 0…2. uCommon умножается на этот коэффициент. | A8 / C1 / C3: принудительно 0. L1–L5: срабатывание лимитера. 1 — лимитеры не режут. |
| uCommon_TEN | экв. 0…2 | Выход ПИ по eT_common, уже умноженный на heatScale01. Общий запрос мощности на сторону до балансировки. | При heatScale01=0 должно быть 0. Иначе растёт, если T_sup ниже уставки (eT_common > 0). |
| trim_TEN | экв. ТЭНа | Баланс лево/право: kTrim × (mL − mR), ограничен leftRightTrimMaxEq. Считается только если годны **обе** подачи, иначе 0. | A1 и A4: ненулевой при разнице mL и mR. A2, A3, A5–A8: строго 0. |
| uLeft_TEN | экв. 0…2 | Запрос на левую сторону: clamp(uCommon − trim, 0…2). Дальше дискретизация в два ТЭНа. | При trim=0 ≈ uRight_TEN. При trim≠0 стороны расходятся. |
| uRight_TEN | экв. 0…2 | Запрос на правую сторону: clamp(uCommon + trim, 0…2). | Симметрично uLeft_TEN. |
| leftTen1Duty | 0…1 | Скважность первого ТЭНа слева: clamp(uLeft, 0…1). Вход sigma-delta 1 Гц. | Следствие uLeft. При uLeft=0 оба левых ТЭНа выкл (после minHold). |
| leftTen2Duty | 0…1 | Скважность второго ТЭНа слева: clamp(uLeft − 1, 0…1). Второй ТЭН включается, когда запрос > 1 эквивалента. | Ненулевая только при uLeft > 1. |
| rightTen1Duty | 0…1 | Скважность первого ТЭНа справа: clamp(uRight, 0…1). | Следствие uRight. |
| rightTen2Duty | 0…1 | Скважность второго ТЭНа справа: clamp(uRight − 1, 0…1). | Ненулевая только при uRight > 1. |
| w_sup_avg | кг/кг | Абсолютная влажность подачи: HumidityRatio(T_sup_avg, RH_sup). RH_sup — среднее годных подач, иначе RH возврата, иначе 50 %. | A8: T_sup=0 и RH=50 % → номинал. A7: T и RH с возврата. A4: уставка влажности от T_sup, не от «мёртвого» канала 2. |
| wErr | кг/кг | Ошибка влажности: w_ret_target − w_sup_avg. Уставка w_ret_target считается от T_ret и RH_target фазы. Знак задаёт форсунку (>) или вытяжку (< −deadband). | Подтверждает, от какой T_ret строится уставка (mRet или подстановка T_sup). |
| injDuty | 0…1 | Скважность форсунки по (wErr − deadband) × injGain. Обнуляется, если включена вытяжка (взаимоисключение). | Вторично для веток Т. 0 при вытяжке или при wErr ≤ deadband. |
| rate_Cps | °C/с | Скорость прогрева горячей точки продукта: (fishHot − предыдущая)/1 с. Лимитер fishHotRateMax. В AirOnly всегда 0. | P1–P3: живое значение. P4 / C2–C4: 0 — маркер, что лимитер продукта не считается. |
| fishHot_C | °C | Самая тёплая точка продукта (max годных датчиков 3 и 4, при одном — этот датчик). Лимиты fishHotMax и скорости. В AirOnly принудительно 0. | P1: max(T3,T4). P2: T3. P3: T4. P4 и AirOnly: **0** — главный маркер ветки без продукта. |
| fishCold_C | °C | Самая холодная точка продукта. Выбор фазы SelectPhase и автостоп при ≥ fishColdTarget. В AirOnly принудительно 0. | P5: смена phase. P6: стоп. C1: стоп по продукту при мёртвом воздухе. AirOnly: 0, стоп только по maxRuntime. |

Три формулы для разбора ветки:

- `T_sup_avg = supplySet_C[phase] − eT_common`
- AirOnly: `fishHot_C = fishCold_C = 0` и `rate_Cps = 0`
- Стороны нагрева сбалансированы: `trim_TEN = 0` и `uLeft ≈ uRight`. Полный отказ воздуха 0…2: `heatScale01 = 0`

## Порядок прогона

| Шаг | Что фиксируем | Зачем |
|-----|----------------|-------|
| 0 | Эталон I1, все датчики годны | База: классические формулы и trim |
| 1 | Три способа исключения I2–I4 на одном канале | KT-0 одинаково режет канал |
| 2 | Матрица продукта P1–P4, затем фазы и автостоп P5–P6 | Ветвление `ControlStep1s` / AirOnly |
| 3 | Матрица воздуха A1–A8 при живом продукте | `ComputeDefrostAirControlInputs` |
| 4 | Лимитеры L1–L5 | `heatScale` не берёт мёртвые каналы |
| 5 | Комбинации C1–C5 | Стык продукта и воздуха, останов |
| 6 | Возврат связи I5 | Канал снова входит в ту же KT |

## KT-0. Критерий участия канала

| ID | Контрольная точка | Как задать | Ожидаемая ветка | Что смотреть | Пройдено |
|----|-------------------|------------|-----------------|--------------|----------|
| I1 | Эталон: все 0…4 годны | Active=1, UseInDefrost=1, Alarm=0. Авторежим | T_sup=(mL+mR)/2, T_ret=mRet, trim по eT_diff, fishHot=max, fishCold=min, фаза по T_cold | phase по T_cold; trim≠0 при разнице mL и mR; fishHot≠fishCold | ☐ |
| I2 | Исключение вручную | Продукт: Settings1 или сервер. Воздух 0…2: `sensorUseInDefrost` на сервере | Канал не в расчёте. Active может остаться 1. T на экране видна | T_filt канала есть; eT_common / fishHot / trim как при «канала нет» | ☐ |
| I3 | Физический обрыв | Отключить от шины, 3 ошибки приёма подряд | Active=0, бит Sensor_AlarmFlags, бит 12 Device_AlarmFlags. «--» красным. Телеметрия −32768 | Алгоритм как при отсутствии канала. Device_Alarm=1 | ☐ |
| I4 | Исключение по шуму | T_ClampHit > TQ/2 в полном буфере (или бит отладчиком) | Канал исключён, сырая T на экране остаётся. АВАРИЯ. Штатного сброса шума нет | То же ветвление, что при Active=0 / UseInDefrost=0 | ☐ |
| I5 | Возврат связи | После I3 подключить датчик | Active=1, comm-lost снят, канал снова в расчёте. Бит шума сам не снимется | Возврат к ветке «канал исправен» | ☐ |

## KT-P. Ветвление по датчикам продукта (3, 4)

Точка: `ControlStep1s` — выбор fishHot/fishCold либо `return` в `ControlStep1s_AirOnly`.
Фаза с продуктом: `SelectPhase(T_cold)`: &lt; −2 WarmUp, &lt; 1 Plateau, иначе Finish.
Без продукта: `SelectPhaseByTime(runtime)`.

| ID | Контрольная точка | Как задать | Ожидаемая ветка | Что смотреть | Пройдено |
|----|-------------------|------------|-----------------|--------------|----------|
| P1 | Оба датчика продукта | 3 и 4 годны. Разные T, например −4 и +0.5 °C | fishHot=max, fishCold=min, ΔT=разница. Фаза по более холодному. Лимит ΔT_fish действует | fishHot/fishCold = max/min T_filt[3], T_filt[4]; phase=SelectPhase(fishCold) | ☐ |
| P2 | Только датчик 3 | Исключить 4. Канал 3 годен | fishHot=fishCold=T3, ΔT=0. Лимит неравномерности не срабатывает. Автостоп по T3 ≥ fishColdTarget | fishHot_C = fishCold_C = T_filt[3] | ☐ |
| P3 | Только датчик 4 | Исключить 3. Канал 4 годен | fishHot=fishCold=T4, ΔT=0. Фаза и автостоп только по T4 | fishHot_C = fishCold_C = T_filt[4] | ☐ |
| P4 | Нет продукта → AirOnly | Исключить 3 и 4. Воздух оставить. Укоротить таймеры AirOnly | Фаза по времени, не по T рыбы. fishHot/fishCold в логе = 0. Стоп по maxRuntime, не по fishColdTarget | phase на границах времени; fishHot=0, fishCold=0; rate_Cps=0 | ☐ |
| P5 | Фазы WarmUp / Plateau / Finish | ≥1 датчик продукта. T_cold: &lt;−2; [−2…1); ≥1 | phase 0 / 1 / 2. Меняются supplySet, supplyMax, RH_target, лимиты | phase; eT_common = supplySet[phase] − T_sup_avg | ☐ |
| P6 | Автостоп по целевой T | Режим с продуктом. debugDisableTargetTStop=0. T_cold ≥ fishColdTarget (завод 6 °C) | Алгоритм останавливается, shutdown. В AirOnly порог не действует | enabled→0; шаги остановки | ☐ |

Точка: `ComputeDefrostAirControlInputs`. Те же правила в режиме с продуктом и в AirOnly.
Смещение оценки подачи при живом возврате: **+2 °C**.

| ID | L | R | Ret | Как задать | Ожидаемая ветка | Что смотреть | Пройдено |
|----|---|---|-----|------------|-----------------|--------------|----------|

| A4 | ✓ | ✓ | ✗ | Исключить 2 | T_sup среднее подач. T_ret:=T_sup. trim вкл | w_ret_target от T_sup, не от мёртвого mRet | ☐ |
| A5 | ✓ | ✗ | ✗ | Исключить 1 и 2 | T_sup=mL, T_ret=mL, trim=0. Мёртвый mR не гасит нагрев | eT_common = supplySet − mL; heatScale не 0, если mL≤supplyMax | ☐ |
| A6 | ✗ | ✓ | ✗ | Исключить 0 и 2 | T_sup=mR, T_ret=mR, trim=0 | eT_common = supplySet − mR; trim=0 | ☐ |
| A7 | ✗ | ✗ | ✓ | Исключить 0 и 1 | T_sup=mRet+2. T_ret=mRet. RH возврата. trim=0. Лимит по (mRet+2) | eT_common = supplySet − (mRet+2); при mRet+2>supplyMax → heatScale=0 | ☐ |
| A8 | ✗ | ✗ | ✗ | Исключить 0,1,2 | T_sup=0, RH=50%, heatScale=0, нагрев выкл. Цикл не падает | heatScale01=0; uCommon=0; ТЭНы выкл после hold | ☐ |

## Стендовые упрощения

- Для P4 / C2–C4 временно уменьшить `airOnlyPhaseWarmUp_s`, `airOnlyPhasePlateau_s` и `maxRuntime_s`.
- Для автостопа продукта снизить `fishColdTarget` или поднять T датчика — не ждать заводские 6 °C.
- Не судить о ветке по сырой T на экране: алгоритм берёт Param 4 (`T_filt`). Исключённый канал может продолжать отображаться.
- UseInDefrost воздуха 0…2 задаётся с сервера; продукт — тумблеры Settings1.
- Шумовая защёлка держится до внешнего сброса / перезапуска.

Код: `DefrostAirThChannelUsable`, `ComputeDefrostAirControlInputs`, `ControlStep1s`, `ControlStep1s_AirOnly`.
