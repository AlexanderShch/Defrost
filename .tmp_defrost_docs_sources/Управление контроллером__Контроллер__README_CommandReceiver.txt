# CommandReceiver Module

## Актуальный порядок работы

В рабочем режиме сервер инициирует обмен. Команда сервера имеет формат [Type][Code][DataLen][Data][CRC16], ответ контроллера — [AA 55][Type][Code][Status][DataLen][Data][CRC16]. CRC Modbus вычисляется без AA 55 и передаётся младшим байтом вперёд. Длина поля DataLen относится только к Data.

При запуске STM32 сервер запрашивает версию и группы параметров 5, 6 и 7, затем устанавливает интервал. Запрос группы 7 ограничен общим бюджетом 950 мс. После запуска сервер периодически отправляет SEND_STATE (03/08) с байтом 01. Ответ 03/08 содержит 60 байт базовой телеметрии и байт флагов. Бит 0 (смещение 60 в Data) означает, что есть события. Старый запрос без параметров получает 60 байт. Для получения флага отдельной команды нет.

Сервер отвечает на телеметрию DATA_OK или DATA_FALSE (00/01 или 00/02). В авторежиме после DATA_OK контроллер отправляет лог регулирования 00/01 с 113 байтами данных. Сервер также читает прежние варианты лога с 89, 105 и 109 байтами. Повтор неизменившейся телеметрии с ошибочной CRC сервер подтверждает DATA_OK и отбрасывает.

В RAM контроллера 16 мест общей очереди. Диагностика занимает до 12 мест, четыре места доступны кнопкам даже при заполнении диагностикой. Записываются обработанные физические СТАРТ и СТОП, первый отказ активного датчика в серии и восстановление. Переполнения считаются раздельно для кнопок и диагностики. Перезагрузка очищает очередь.

По флагу сервер читает головную запись командой GET_EVENT (03/0D) и записывает её в log.txt. После принудительной записи файла сервер отправляет ACK_EVENT (03/0E), и контроллер удаляет выданную запись. Повтор не создаёт дубликата строки благодаря идентификатору загрузки и номеру события. При наличии следующих событий сервер продолжает чтение. Флаг служебный и в WorkData не экспортируется.


## Краткое описание

Модуль для приема и обработки команд от сервера через COM-порт (UART4) в системе управления дефростером на базе STM32F429.

## Основные возможности

✓ Прием команд от сервера через COM-порт (UART4)  
✓ Проверка целостности данных через CRC16  
✓ Обработка команд управления (START, STOP, PAUSE, RESUME, RESET)  
✓ Обработка команд конфигурации (установка температуры, интервала, режима)  
✓ Обработка команд запроса данных (статус, версия, конфигурация)  
✓ Автоматическая отправка ответов на команды  
✓ Работа в отдельном потоке FreeRTOS  
✓ Статистика обработки команд  

## Быстрый старт

### 1. Добавление в проект

Скопируйте файлы `CommandReceiver.hpp` и `CommandReceiver.cpp` в папку `ProjectCode/`.

### 2. Интеграция в main.c

**Добавьте в секцию включений:**
```c
#include "C2CPP.hpp"
```

**Объявите поток:**
```c
osThreadId_t RX_From_ServerHandle;
const osThreadAttr_t RX_From_Server_attributes = {
  .name = "RX_From_Server",
  .stack_size = 512 * 4,
  .priority = (osPriority_t) osPriorityNormal,
};
```

**Создайте поток:**
```c
RX_From_ServerHandle = osThreadNew(CommandReceiver_Task_C, NULL, &RX_From_Server_attributes);
```

### 3. Тестирование

**Запустите Python скрипт:**
```bash
python test_commands.py --port COM3 --baudrate 19200
```

**Или отправьте команду вручную:**
- Команда START (HEX): `010100C180`
- Команда STOP (HEX): `0102008181`

## Формат команды

```
┌──────────────┬──────────────┬──────────────┬─────────────┬──────────┐
│ Command Type │ Command Code │ Data Length  │    Data     │  CRC16   │
│   (1 byte)   │   (1 byte)   │   (1 byte)   │  (0-59 b)   │ (2 bytes)│
└──────────────┴──────────────┴──────────────┴─────────────┴──────────┘
```

## Типы команд

| Тип | Название       | Описание                 |
|-----|----------------|--------------------------|
| 0x01| CONTROL        | Управление устройством   |
| 0x02| CONFIGURATION  | Настройка параметров     |
| 0x03| REQUEST        | Запрос данных            |
| 0x04| RESPONSE       | Ответ от устройства      |

## Команды управления (CONTROL)

| Код  | Команда | Описание                |
|------|---------|-------------------------|
| 0x01 | START   | Запуск устройства       |
| 0x02 | STOP    | Остановка устройства    |
| 0x03 | PAUSE   | Приостановка работы     |
| 0x04 | RESUME  | Возобновление работы    |
| 0x05 | RESET   | Сброс устройства        |

## Команды конфигурации (CONFIGURATION)

| Код  | Команда           | Параметры        | Описание                  |
|------|-------------------|------------------|---------------------------|
| 0x01 | SET_TEMPERATURE   | float (4 bytes)  | Установить температуру    |
| 0x02 | SET_INTERVAL      | uint16 (2 bytes) | Установить интервал       |
| 0x03 | SET_MODE          | uint8 (1 byte)   | Установить режим (0/1)    |

## Команды запроса (REQUEST)

| Код  | Команда      | Описание                     |
|------|--------------|------------------------------|
| 0x01 | GET_STATUS   | Получить статус устройства   |
| 0x02 | GET_VERSION  | Получить версию прошивки     |
| 0x03 | GET_CONFIG   | Получить конфигурацию        |

## Архитектура

```
        Сервер
           │
           │ COM-порт (UART4)
           │
           ↓
    ┌──────────────────┐
    │ CommandReceiver  │
    │     Task         │ ← Отдельный поток FreeRTOS
    └──────────────────┘
           │
           ├─→ Прием команд (DMA + IDLE)
           ├─→ Проверка CRC16
           ├─→ Обработка команд
           └─→ Отправка ответов
```

## Обработка команд

1. **Прием**: Прием по UART4 с использованием DMA и прерывания IDLE
2. **Проверка CRC**: Валидация контрольной суммы
3. **Парсинг**: Извлечение типа команды, кода и данных
4. **Выполнение**: Вызов соответствующего обработчика
5. **Ответ**: Отправка подтверждения/результата серверу

## Расширение функционала

### Добавление новой команды

1. Добавить код команды в enum в `CommandReceiver.hpp`
2. Добавить обработчик в соответствующую функцию в `CommandReceiver.cpp`
3. Обновить документацию

**Пример:**
```cpp
// В CommandReceiver.hpp
typedef enum {
    CFG_CMD_SET_TEMPERATURE = 0x01,
    CFG_CMD_SET_INTERVAL = 0x02,
    CFG_CMD_SET_MODE = 0x03,
    CFG_CMD_NEW_COMMAND = 0x04  // Новая команда
} ConfigCommand_t;

// В CommandReceiver.cpp - функция CommandReceiver_HandleConfiguration
case CFG_CMD_NEW_COMMAND:
{
    // Обработка новой команды
    // ...
    break;
}
```

## FAQ

**Q: Как изменить COM-порт?**  
A: В `CommandReceiver.cpp` измените `huart4` на нужный UART и обновите GPIO пины.

**Q: Как изменить скорость обмена?**  
A: Настройте UART4 в CubeMX или в `MX_UART4_Init()` в `main.c`.

**Q: Почему не приходят команды?**  
A: Проверьте:
- Правильность подключения TX/RX
- Скорость обмена
- Формат команды и CRC
- Что поток RX_From_Server создан и запущен

**Q: Как добавить логирование?**  
A: Настройте printf через UART или добавьте запись в память/SD-карту.
