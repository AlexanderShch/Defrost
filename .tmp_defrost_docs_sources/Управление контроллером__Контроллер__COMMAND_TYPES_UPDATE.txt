# Обновление типов команд CommandReceiver

## Актуальный порядок работы

Ниже сохранено описание исследованной версии. Для текущего кода действуют следующие правила.

В рабочем режиме сервер инициирует обмен. Команда сервера имеет формат [Type][Code][DataLen][Data][CRC16], ответ контроллера — [AA 55][Type][Code][Status][DataLen][Data][CRC16]. CRC Modbus вычисляется без AA 55 и передаётся младшим байтом вперёд. Длина поля DataLen относится только к Data.

При запуске STM32 сервер запрашивает версию и группы параметров 5, 6 и 7, затем устанавливает интервал. Запрос группы 7 ограничен общим бюджетом 950 мс. После запуска сервер периодически отправляет SEND_STATE (03/08) с байтом 01. Ответ 03/08 содержит 60 байт базовой телеметрии и байт флагов. Бит 0 (смещение 60 в Data) означает, что есть события. Старый запрос без параметров получает 60 байт. Для получения флага отдельной команды нет.

Сервер отвечает на телеметрию DATA_OK или DATA_FALSE (00/01 или 00/02). В авторежиме после DATA_OK контроллер отправляет лог регулирования 00/01 с 113 байтами данных. Сервер также читает прежние варианты лога с 89, 105 и 109 байтами. Повтор неизменившейся телеметрии с ошибочной CRC сервер подтверждает DATA_OK и отбрасывает.

В RAM контроллера 16 мест общей очереди. Диагностика занимает до 12 мест, четыре места доступны кнопкам даже при заполнении диагностикой. Записываются обработанные физические СТАРТ и СТОП, первый отказ активного датчика в серии и восстановление. Переполнения считаются раздельно для кнопок и диагностики. Перезагрузка очищает очередь.

По флагу сервер читает головную запись командой GET_EVENT (03/0D) и записывает её в log.txt. После принудительной записи файла сервер отправляет ACK_EVENT (03/0E), и контроллер удаляет выданную запись. Повтор не создаёт дубликата строки благодаря идентификатору загрузки и номеру события. При наличии следующих событий сервер продолжает чтение. Флаг служебный и в WorkData не экспортируется.


## ✅ Внесенные изменения

Типы команд были изменены согласно новым требованиям:

### Старые типы команд (УДАЛЕНЫ):
```
- CONTROL (0x01)        - Команды управления
- RESPONSE (0x04)       - Ответы от устройства
```

### Новые типы команд:
```
- PROG_CONTROL (0x01)       - Команды управления программой (СТАРТ, СТОП и т.д.)
- CONFIGURATION (0x02)      - Команды конфигурации (без изменений)
- REQUEST (0x03)            - Команды запроса данных (без изменений)
- DEVICE_CONTROL (0x04)     - Команды управления устройствами (НОВЫЙ)
```

### Тип для ответов:
```
- RESPONSE (0x80)           - Используется внутри модуля для ответов
```

## 📋 Полная таблица команд

### 1. PROG_CONTROL (0x01) - Управление программой

| Код  | Команда | HEX байты     | Описание                        |
|------|---------|---------------|---------------------------------|
| 0x01 | START   | 01 01 00 XX XX| Запуск программы (авто режим)   |
| 0x02 | STOP    | 01 02 00 XX XX| Остановка программы             |
| 0x03 | PAUSE   | 01 03 00 XX XX| Приостановка программы          |
| 0x04 | RESUME  | 01 04 00 XX XX| Возобновление программы         |
| 0x05 | RESET   | 01 05 00 XX XX| Сброс программы                 |

**Действие команд:**
- **START**: Переключает в автоматический режим (`Model::Flag_DFR_manual = 0`)
- **STOP**: Переключает в ручной режим и выключает все устройства
- **PAUSE**: Переключает в ручной режим, сохраняя текущее состояние
- **RESUME**: Возвращает в автоматический режим
- **RESET**: Выполняет программный сброс параметров

---

### 2. DEVICE_CONTROL (0x04) - Управление устройствами

| Код  | Команда      | Параметры    | HEX пример           | Описание                         |
|------|--------------|--------------|----------------------|----------------------------------|
| 0x01 | RELAY_ON     | 1 байт (№)   | 04 01 01 00 XX XX   | Включить реле № (0-15)          |
| 0x02 | RELAY_OFF    | 1 байт (№)   | 04 02 01 00 XX XX   | Выключить реле № (0-15)         |
| 0x03 | RELAY_SET    | 2 байта (маска)| 04 03 02 FF 0F XX XX| Установить маску всех реле     |
| 0x04 | HEATER_ON    | нет          | 04 04 00 XX XX      | Включить все нагреватели (ТЭНы) |
| 0x05 | HEATER_OFF   | нет          | 04 05 00 XX XX      | Выключить все нагреватели       |
| 0x06 | FAN_ON       | нет          | 04 06 00 XX XX      | Включить все вентиляторы        |
| 0x07 | FAN_OFF      | нет          | 04 07 00 XX XX      | Выключить все вентиляторы       |

**Примеры использования:**

1. **Включить реле № 3:**
   ```
   04 01 01 03 XX XX
   │  │  │  │  └─┴─ CRC16
   │  │  │  └───── Номер реле (3)
   │  │  └──────── Длина данных (1 байт)
   │  └─────────── Команда RELAY_ON
   └────────────── Тип DEVICE_CONTROL
   ```

2. **Установить состояние всех реле (включить 0,1,2,3 биты):**
   ```
   04 03 02 0F 00 XX XX
   │  │  │  │  │  └─┴─ CRC16
   │  │  │  └──┴────── Маска 0x000F (биты 0-3)
   │  │  └──────────── Длина данных (2 байта)
   │  └─────────────── Команда RELAY_SET
   └────────────────── Тип DEVICE_CONTROL
   ```

**Действие команд:**
- Все команды DEVICE_CONTROL переключают систему в ручной режим (`Model::Flag_DFR_manual = 1`)
- **RELAY_ON/OFF**: Управляют отдельными битами в регистре `Model::DFR_manual`
- **RELAY_SET**: Устанавливают всю битовую маску регистра `Model::DFR_manual`
- **HEATER_ON/OFF**: Управляют ТЭНами (Ten1_Left, Ten2_Left, Ten1_Right, Ten2_Right)
- **FAN_ON/OFF**: Управляют вентиляторами (Fan1_Left, Fan2_Left, Fan1_Right, Fan2_Right)

---

### 3. CONFIGURATION (0x02) - Конфигурация (без изменений)

| Код  | Команда          | Параметры        | HEX пример              | Описание                  |
|------|------------------|------------------|-------------------------|---------------------------|
| 0x01 | SET_TEMPERATURE  | 4 байта (float)  | 02 01 04 00 00 CC 41 XX XX | Установить температуру |
| 0x02 | SET_INTERVAL     | 2 байта (uint16) | 02 02 02 0A 00 XX XX    | Установить интервал       |
| 0x03 | SET_MODE         | 1 байт (uint8)   | 02 03 01 00 XX XX       | Установить режим (0/1)    |

---

### 4. REQUEST (0x03) - Запросы данных (без изменений)

| Код  | Команда      | HEX байты      | Описание                     |
|------|--------------|----------------|------------------------------|
| 0x01 | GET_STATUS   | 03 01 00 XX XX | Запросить статус устройства  |
| 0x02 | GET_VERSION  | 03 02 00 XX XX | Запросить версию прошивки    |
| 0x03 | GET_CONFIG   | 03 03 00 XX XX | Запросить конфигурацию       |

## 🔄 Формат ответов

Ответы от устройства используют тип **RESPONSE (0x80)**:

```
┌──────────────┬──────────────┬──────────────┬──────────────┬─────────────┬──────────┐
│   Response   │    Orig.     │    Status    │     Data     │    Data     │  CRC16   │
│     Type     │  Cmd Code    │              │    Length    │             │          │
│   (0x80)     │   (1 byte)   │   (1 byte)   │   (1 byte)   │  (0-59 b)   │(2 bytes) │
└──────────────┴──────────────┴──────────────┴──────────────┴─────────────┴──────────┘
```

**Коды статуса:**
- 0x00 - OK (успешно выполнено)
- 0x01 - CRC ERROR (ошибка контрольной суммы)
- 0x02 - INVALID TYPE (неверный тип команды)
- 0x03 - INVALID CODE (неверный код команды)
- 0x04 - INVALID LENGTH (неверная длина данных)
- 0x05 - EXECUTION ERROR (ошибка выполнения)
- 0x06 - TIMEOUT (таймаут)
- 0xFF - UNKNOWN ERROR (неизвестная ошибка)

## ⚠️ Важные замечания

1. **Автоматический vs Ручной режим:**
   - Команды **PROG_CONTROL** управляют автоматическим режимом программы
   - Команды **DEVICE_CONTROL** переключают в ручной режим и управляют устройствами напрямую

2. **Приоритет управления:**
   - Если используются команды DEVICE_CONTROL, система переключается в ручной режим
   - Для возврата к автоматическому управлению используйте PROG_CONTROL -> START

3. **Совместимость:**
   - Старые команды с типом 0x01 теперь интерпретируются как PROG_CONTROL
   - Команды с типом 0x04 теперь интерпретируются как DEVICE_CONTROL (не RESPONSE)
   - Ответы используют специальный тип 0x80

## 📞 Вопросы и решение проблем

**Q: Как теперь включить нагреватели?**  
A: Используйте команду `DEVICE_CONTROL.HEATER_ON` (04 04 00 XX XX)

**Q: Как вернуться в автоматический режим после ручного управления?**  
A: Используйте команду `PROG_CONTROL.START` (01 01 00 XX XX)

**Q: Будут ли работать старые команды?**  
A: Команды PROG_CONTROL (0x01) будут работать, но поведение изменилось - они управляют режимом программы, а не устройствами напрямую.
