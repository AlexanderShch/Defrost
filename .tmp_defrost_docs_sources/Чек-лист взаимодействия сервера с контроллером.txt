# Чек-лист взаимодействия сервера с контроллером

## Актуальный порядок работы

Контроллер опрашивает датчики и модуль ввода-вывода по Modbus RTU через UART5. Для каждого запроса ожидаемую длину вычисляют по функции и числу запрошенных регистров или битов. Обычно это 9 байт для двух регистров, 7 для одного регистра или 16 дискретных входов или выходов, 8 для подтверждения записи и 5 для ответа с исключением Modbus.

До обновления показаний контроллер проверяет состояние UART и факт приёма, границы кадра, адрес, функцию и соответствие фактической длины запросу. Для чтения проверяется ByteCount, затем CRC по фактически принятому кадру. Ответ с исключением проверяется отдельно по длине и CRC. При ошибке чтения контроллер удерживает предыдущие показания.

После трёх подряд ошибок приёма активный датчик переходит в Active=0. Контроллер продолжает пробные опросы. Неудачные опросы неактивного устройства не увеличивают счётчики ошибок, не попадают в минутную сводку и не создают события. Первый правильный ответ снова включает устройство. Если до отключения была открыта серия сбоев, правильный ответ завершает её событием восстановления. UseInDefrost управляет участием в регулировании независимо от активности на шине.

Минутная диагностика GET_SENSOR_DIAG (03/0A) возвращает 85 байт данных со статистикой по устройствам и снимком последнего сбоя. Счётчики периода сбрасываются при формировании ответа. Сбой активного устройства и его восстановление отдельно передаются через очередь событий с подтверждением.

В рабочем режиме сервер инициирует обмен. Команда сервера имеет формат [Type][Code][DataLen][Data][CRC16], ответ контроллера — [AA 55][Type][Code][Status][DataLen][Data][CRC16]. CRC Modbus вычисляется без AA 55 и передаётся младшим байтом вперёд. Длина поля DataLen относится только к Data.

При запуске STM32 сервер запрашивает версию и группы параметров 5, 6 и 7, затем устанавливает интервал. Запрос группы 7 ограничен общим бюджетом 950 мс. После запуска сервер периодически отправляет SEND_STATE (03/08) с байтом 01. Ответ 03/08 содержит 60 байт базовой телеметрии и байт флагов. Бит 0 (смещение 60 в Data) означает, что есть события. Старый запрос без параметров получает 60 байт. Для получения флага отдельной команды нет.

Сервер отвечает на телеметрию DATA_OK или DATA_FALSE (00/01 или 00/02). В авторежиме после DATA_OK контроллер отправляет лог регулирования 00/01 с 113 байтами данных. Сервер также читает прежние варианты лога с 89, 105 и 109 байтами. Повтор неизменившейся телеметрии с ошибочной CRC сервер подтверждает DATA_OK и отбрасывает.

В RAM контроллера 16 мест общей очереди. Диагностика занимает до 12 мест, четыре места доступны кнопкам даже при заполнении диагностикой. Записываются обработанные физические СТАРТ и СТОП, первый отказ активного датчика в серии и восстановление. Переполнения считаются раздельно для кнопок и диагностики. Перезагрузка очищает очередь.

По флагу сервер читает головную запись командой GET_EVENT (03/0D) и записывает её в log.txt. После принудительной записи файла сервер отправляет ACK_EVENT (03/0E), и контроллер удаляет выданную запись. Повтор не создаёт дубликата строки благодаря идентификатору загрузки и номеру события. При наличии следующих событий сервер продолжает чтение. Флаг служебный и в WorkData не экспортируется.

При выходе сервер ставит оставшиеся данные в очередь фонового экспорта, закрывает окна и завершает процесс после окончания записи Excel либо по тайм-ауту ожидания (5 минут).


Источник: программа испытаний (блок «рабочие ситуации связи») + `ProjectServerW` + `CommandReceiver.cpp`.
Кодировка: UTF-8.

Цель: подтвердить, что сервер корректно ставит и теряет связь, принимает телеметрию и лог, управляет авторежимом и пишет Excel.

Модель обмена: **одна команда в полёте**. Команда сервера **без** `AA 55`. Ответ контроллера **с** маркером `AA 55`. Интервал `SEND_STATE` хранит **сервер**; `SET_INTERVAL` на МК — только ACK.

## Порядок прогона

| Шаг | Блок | Зачем |
|-----|------|-------|
| 0 | L1 | База: связь и стартовая последовательность |
| 1 | T1–T4 | Регулярный обмен телеметрия + лог |
| 2 | S1–S4 | ПУСК / СТОП / чужой старт / Excel по окончании |
| 3 | S5–S8 | Повторный ПУСК, автозапуск, автоперезапуск, СБРОС |
| 4 | P1–P5 | Параметры и интервал |
| 5 | A1–A2, E1–E4 | Аварии и файлы |
| 6 | L2–L6 | Обрыв, переподключение, битый кадр, таймаут |

## Кадры

| Направление | Смысл | Type/Code | Данные |
|-------------|-------|-----------|--------|
| Сервер → МК | Команда | `[Type][Code][DataLen][Data][CRC]` | Без AA 55 |
| МК → сервер | Ответ / телеметрия / лог | `AA 55 [Type][Code][Status][DataLen][Data][CRC]` | CRC по полям после маркера |
| Сервер → МК | DATA_OK | `00 01 00` + CRC | После годной телеметрии |
| МК → сервер | Телеметрия | `03 08`, DataLen=45 | `MSGQUEUE_OBJ_t` |
| МК → сервер | Лог алгоритма | `00 01`, DataLen=89 | `ControlLogPayload_t`, только после DATA_OK |
| Сервер → МК | START / STOP / RESET | `01 01` / `01 02` / `01 05` | Сначала ACK, затем действие на МК |
| Сервер → МК | GET_ALARM_FLAGS | `03 09` | Ответ 4 байта LE: Device_AlarmFlags + Sensor_AlarmFlags |

## Связь и целостность кадров

| ID | Событие | Как вызвать | Ожидаемое взаимодействие | Доказательство | Пройдено |
|----|---------|-------------|--------------------------|----------------|----------|
| L1 | Установка связи | Открыть окно приёма, подключить контроллер | Сокет принят. GET_VERSION → GET_DEFROST_GROUP 5, 6 и 7 → SET_INTERVAL. Затем таймер SEND_STATE | Лог «Последовательность запуска выполнена». Версия на форме. Таблицы 5/6 заполнены. Идут строки телеметрии | ☐ |
| L2 | Потеря связи | Оборвать кабель / мост / питание МК | Команды не считаются успешными. `_Wrk` сбрасывается, если телеметрии нет дольше интервал+1 с | Таймауты в логе. Таблица не растёт. UI не остаётся «запущено» вслепую | ☐ |
| L3 | Повторная связь после обрыва | Сразу восстановить соединение, не ждать Excel | Новое соединение сразу. Стартовая последовательность снова. Старый Excel в фоне | Повтор GET_VERSION / SET_INTERVAL / групп 5,6. Файл предыдущей сессии на диске | ☐ |
| L4 | Связь после закрытия окна приёма | Закрыть DataForm, открыть снова, подключить | Форма закрывается сразу (Excel в фоне). Старт как L1 | Нет зависания на записи Excel. Новый сеанс телеметрии | ☐ |
| L5 | Потеря / порча части пакета | Короткий кадр, битый CRC | Кадр отброшен, сервер жив. При плохой телеметрии — DATA_FALSE, лог за такт не клеится | Лог CRC/длины. Следующий годный кадр принимается | ☐ |
| L6 | Нет ответа на команду | START/GET_VERSION на оборванной линии | Таймаут. UI не переключается «как будто OK» | Нет ложного успеха. Single in-flight до истечения ожидания | ☐ |

## Телеметрия и лог

| ID | Событие | Как вызвать | Ожидаемое взаимодействие | Доказательство | Пройдено |
|----|---------|-------------|--------------------------|----------------|----------|
| T1 | Цикл SEND_STATE → телеметрия → DATA_OK → лог | Связь есть, интервал например 10 с | Сервер `03 08` → кадр 45 байт → `00 01` → лог 89 байт | Строка таблицы: телеметрия, затем поля T_filt / phase / eT_common. Без DATA_OK лога нет | ☐ |
| T2 | Телеметрия и лог одного такта | Сравнить Time строки с логом | Лог в pending-строку того же Time. Новая телеметрия раньше лога — старая строка фиксируется без лога | Нет сдвига лога на соседнюю секунду | ☐ |
| T3 | Маркер «нет данных» датчика | Обрыв датчика, 3 ошибки Rx | Телеметрия −32768. На форме «--» / пусто. В Excel пустая ячейка | Не путать сырую T телеметрии с T_filt лога | ☐ |
| T4 | Признак авторежима по _Wrk | ПУСК с сервера или старт с МК / EEPROM | `_Wrk=1` → СТОП доступен. Нет _Wrk дольше интервал+1 с → «можно запустить» | UI синхронен с телеметрией, даже если START слал не этот сеанс | ☐ |

## Сеанс автоматического режима

| ID | Событие | Как вызвать | Ожидаемое взаимодействие | Доказательство | Пройдено |
|----|---------|-------------|--------------------------|----------------|----------|
| S1 | Команда СТАРТ | _Wrk=0, кнопка ПУСК | Контроллер: ACK, затем SetEnabled(1). UI меняется только после OK | Лог START OK. Телеметрия `_Wrk=1` | ☐ |
| S2 | Команда СТОП | Автомат идёт | ACK, SetEnabled(0), shutdown. Excel не сразу: 10 тактов `_Wrk=0` и `_Shd=0` | Лог STOP OK. Затем очередь Excel | ☐ |
| S3 | Начало авторежима, увиденное сервером | Старт с экрана МК или после питания | Сервер START не шлёт. По `_Wrk=1` пишет сессию | Таблица растёт без нажатия ПУСК на ПК | ☐ |
| S4 | Окончание авторежима | Цель T / maxRuntime / СТОП | Shutdown в телеметрии, Excel после 10 спокойных тактов. Перед экспортом GET_ALARM_FLAGS | Файл WorkData_Port….xlsx, листы параметров и аварий | ☐ |
| S5 | Новый ПУСК до конца сеанса | _Wrk=1, попытка ПУСК / автозапуск | Кнопка недоступна. Автозапуск пропускается, галка снимается. Повторный START с сервера не слать (МК всё равно ACK+enable) | Нет второй чистой сессии в той же таблице | ☐ |
| S6 | Автозапуск по времени | Время +1–2 мин, галка, связь, программа не запущена, форма открыта | В эту минуту (±30 с) уходит START, галка снимается (один раз) | Лог «Автозапуск сработал», далее S1 | ☐ |
| S7 | Автоперезапуск по времени | Автомат идёт, время ближайшая минута | STOP → ожидание Excel (таймаут 20 мин) → START. Галка снимается. Нет связи — отмена | Лог STOP → Excel → START | ☐ |
| S8 | Команда СБРОС | RESET с формы | ACK, рестарт МК, SEND_STATE стоп. После подъёма — отложенный стартап. Без ACK стартап не планируется | Пауза, снова GET_VERSION / SET_INTERVAL / группы 5,6 | ☐ |

## Стендовые упрощения

- Интервал SEND_STATE 3–5 с, чтобы быстрее набрать 10 тактов для Excel.
- Автозапуск / автоперезапуск — время «сейчас + 1 мин», форма открыта.
- Не слать ПУСК при `_Wrk=1`.
- `SET_INTERVAL` не меняет период на контроллере.
- Excel после **10** тактов `_Wrk=0` и `_Shd=0`.
